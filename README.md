# IdleArc Analyst — с OTA-обновлениями

Аналитика для IdleArc: перехват характеристик из ответов игры, подбор формул
(регрессия), калькулятор урона, оверлей прямо поверх игрового канваса.

**Что добавлено:** полноценная система обновления «по воздуху» (OTA). Теперь
корректировки вносятся через само расширение и применяются у всех, кто его
установил, **без переустановки ZIP/папки** — это особенно важно на Android,
где распакованное расширение обновлять вручную очень неудобно.

---

## Коротко: как это работает

```
ota/source.json  ──(tools/build-ota.mjs)──▶  ota/update.json
                                              │  (любой HTTPS-хост с CORS)
                                              ▼
   service worker раз в час читает файл → проверяет SHA-256 / подпись
                                       → применяет правки
                                       → рассылает их во вкладки игры
```

Расширение **не может заменить свои собственные `.js`-файлы**: MV3 запрещает
`eval` в страницах расширения, а `chrome.storage` и сеть не являются кодом.
Поэтому OTA здесь — это **слой удалённо управляемых настроек и данных**, а не
подмена пакета. Всё, что реально нужно править в таком проекте, вынесено в
этот слой:

| Что меняется | Где применяется |
| --- | --- |
| интервал автоснимков, TTL конфига, лимиты хранения | `background.js` |
| лимит перехватов, регулярки «интересных» ответов, доп. пути API, вкл/выкл fetch/XHR/WS | `inject.js` + `content.js` (на лету, без reload) |
| заголовок оверлея, частота обновления, видимость кнопки, произвольный CSS | `overlay.js` (на лету) |
| подписи/единицы метрик, новые синонимы ключей API, подсказки распознавания | `stats.js` → попап, оверлей и фон |
| объявление игрокам, список изменений, баннер «доступно обновление» | попап, оверлей |
| **полная замена кода перехватчика** (`hookCode`) | MAIN world страницы (только из подписанного канала) |
| флаги `pause_capture`, `sample_all` | перехватчик |

Правки доставляются в открытую вкладку игры сообщением, поэтому регулярки,
лимиты и CSS подхватываются **мгновенно**. Только замена `hookCode` требует
перезагрузки вкладки (в центре обновлений есть кнопка «Перезагрузить игру»).

Если правка требует нового кода интерфейса, которого в старой сборке нет,
ставят `minExtension` — расширение покажет «требуется свежая сборка» и не
применит документ. Это единственный случай, когда нужен новый ZIP.

## Быстрый старт

### Вариант 1 — этот репозиторий (по умолчанию)

Канал уже прописан в `ota-config.js`:

```
https://raw.githubusercontent.com/AlfaGideon/IdleeArcAnalitics/main/ota/update.json
```

1. Соберите файл канала: `node tools/build-ota.mjs` (файл `ota/update.json` уже
   лежит в репозитории).
2. Закоммитьте/запушьте **в `main`** (или просто опубликуйте из расширения).
   Если работаете в другой ветке или форке — либо влейте изменения в `main`,
   либо поменяйте URL на вкладке «Канал». URL из приватного репозитория
   отдаётся только с авторизацией: для него используйте GitHub Pages, gist
   или свой сервер.
3. Установите расширение (`release/idlearc-analyst.zip`, либо «Загрузить
   распакованное» из корня репозитория).
4. Откройте **OTA** в шапке попапа → «Центр обновлений» → «Проверить сейчас».

Дальше проверка идёт сама: раз в час, при старте браузера и при каждом
открытии вкладки игры (с защитой от слишком частых запросов).

### Вариант 2 — свой хост

Положите `update.json` на GitHub Pages / gist / свой сервер и вставьте прямую
HTTPS-ссылку на вкладке «Канал». Требования: `https://`, ответ `200` с JSON и
заголовок `Access-Control-Allow-Origin: *`. Для нестандартного домена браузер
попросит разрешение при сохранении настроек.

### Вариант 3 — совсем без интернета (Android, офлайн)

Центр обновлений → «Редактор JSON» → «Скачать update.json» → перенести файл на
устройство → «Быстрые правки» → «Импорт update.json с устройства».
Либо «Встроенный канал (офлайн)» — в собранный ZIP уже положена копия
`ota/update.json` под именем `update.json`.

## Как вносить корректировки «просто через расширение»

Откройте центр обновлений (кнопка **OTA** в шапке попапа, кнопка в оверлее,
либо «Настройки → Центр обновлений»).

1. **Быстрые правки** — поля без JSON: заголовок оверлея, интервал снимков,
   лимит перехватов, TTL конфига, доп. пути API, регулярка, частота обновления
   оверлея, объявление игрокам, переключатели «пауза перехвата» /
   «слушать все ответы» / «показывать кнопку». Кнопка «Применить локально»
   действует сразу и поверх канала. «Сбросить локальные правки» убирает её.

2. **Редактор JSON** — полный документ канала. Кнопки:
   - *Шаблон*, *Из применённого канала*, *Форматировать*, *Проверить*;
   - *Применить локально* (только на этом устройстве, мгновенно);
   - *Применить как канал (вручную)* (эмуляция загрузки с сервера);
   - *Скачать update.json* / *Скопировать JSON* — готовый файл с корректным
     `integrity.sha256` (и подписью, если введён приватный ключ);
   - *Опубликовать на GitHub* — записывает документ в репозиторий через API.

3. **Публикация** — owner / repo / branch / path и fine-grained токен с правом
   `Contents: read & write`. Расширение само найдёт `sha` существующего файла,
   сделает `PUT /repos/.../contents/...` и сразу проверит канал заново.
   Токен и приватный ключ лежат только в `chrome.storage.local` этого браузера,
   не попадают в журнал и не экспортируются.

4. **Откат и сброс** — каждая применённая версия попадает в историю (до 6),
   «Откатить последнее обновление» возвращает предыдущую. «Сбросить всё к
   заводским» убирает и канал, и локальные правки. Все наблюдения/снимки при
   этом **не удаляются**.

## Формат `update.json`

```json
{
  "schema": 1,
  "app": "IdleArc Analyst",
  "channel": "stable",
  "version": "1.1.1",
  "publishedAt": "2026-11-02T12:00:00Z",
  "minExtension": "1.1.0",
  "changelog": ["Что изменилось"],
  "announcement": { "level": "info", "text": "Сообщение в попапе и оверлее" },
  "settings": {
    "background": { "snapshotMinGapSec": 60, "configTtlHours": 6 },
    "capture": {
      "limitPerMinute": 400,
      "relevantPattern": "combatStats|attackDamage|dps",
      "extraApiPaths": ["/combat"],
      "enableFetch": true, "enableXHR": true, "enableWS": true
    },
    "overlay": { "title": "IdleArc Analyst", "showFab": true, "refreshMs": 6000 }
  },
  "patch": {
    "metrics": { "strength": { "label": "Сила (новая)", "unit": "" } },
    "synonyms": { "newapikeyname": "strength" },
    "labelHints": [["\\bновая\\s*сила\\b", "strength", "i"]],
    "overlayCss": ".ia-fab{border-radius:50%}",
    "features": { "pause_capture": false, "sample_all": false },
    "hookCode": null
  },
  "integrity": { "sha256": "…", "signature": "… или null", "keyId": "main" }
}
```

Правила:

- Незаданные поля **не перезаписывают** встроенные значения — документ может
  быть коротким. Это же относится к локальным правкам (они «разреженные»).
- `version` — `x.y.z`; применяется только если новее уже применённой.
- `minExtension` / `maxExtension` — защита от несовместимых сборок.
- `integrity.sha256` считается от **канонического JSON** (ключи отсортированы
  на всех уровнях) всего документа кроме `integrity`. Без верного хэша
  удалённый документ отклоняется.
- `patch.hookCode` — произвольный JS для MAIN world. По умолчанию удалённый
  код разрешён **только из подписанного канала**; локальные правки ему доверяют
  всегда. Внедрение идёт через `chrome.scripting` (`world: 'MAIN'`) с откатом
  на `<script>` и на встроенный `inject.js`, если CSP страницы мешает.
- Размеры ограничены: документ ≤ 512 КБ, CSS ≤ 64 КБ, `hookCode` ≤ 200 КБ,
  до 500 синонимов и 200 метрик. Опасные CSS-конструкции (`</style>`,
  `javascript:`, `@import`) вырезаются.

## Подпись канала (рекомендуется для общего канала)

```bash
node tools/keygen.mjs --patch-config     # публичный ключ → ota-config.js
node tools/build-ota.mjs                 # подпишет ota/private.pem
node tools/test-ota.mjs                  # проверит хэш и подпись
```

- `ota/private.pem` в `.gitignore`, не коммитится.
- Для GitHub Actions положите содержимое ключа в секрет `OTA_PRIVATE_KEY` —
  `.github/workflows/ota.yml` пересоберёт `ota/update.json` при изменении
  `ota/source.json`.
- Публичный ключ можно вставить и без пересборки: вкладка «Канал» →
  «Публичный ключ (SPKI, base64)».
- `requireSignature: true` — принимать только подписанные документы.
- Без подписи канал работает (проверяется SHA-256), но `hookCode` и любые
  правки, требующие доверия, отключаются политикой `allowUnsignedCode`.

Подпись — ECDSA P-256 / SHA-256 (WebCrypto), поэтому проверяется и в Chrome,
и в мобильных Chromium-браузерах.

## Инструменты разработчика

| Команда | Что делает |
| --- | --- |
| `node tools/build-ota.mjs` | собрать `ota/update.json` из `ota/source.json`, посчитать хэш/подпись |
| `node tools/build-ota.mjs --now --version 1.1.2` | обновить дату и версию |
| `node tools/keygen.mjs --patch-config` | создать пару ключей и вписать публичный в `ota-config.js` |
| `node tools/make-zip.mjs` | собрать плоский `release/idlearc-analyst.zip` для установки (включает `update.json`) |
| `node tools/test-ota.mjs` | 80 проверок: хэш, подпись, политика, слияние, синтаксис, ссылки манифеста |
| `node tools/test-updater.mjs` | 39 интеграционных проверок с эмуляцией `chrome.*`: проверка канала, локальные правки, импорт, откат, публикация в GitHub |

Зависимостей нет — только Node.js 18+.

## Android / Яндекс.Браузер

- Все файлы расширения по-прежнему лежат **в одном уровне**, без подпапок
  (см. `INSTALL-ANDROID.txt`). Новые `ota-*.js`, `ota.html`, `ota.css`,
  `options.js` тоже в корне.
- В манифесте нет `minimum_chrome_version` и `default_locale`.
- `alarms` на мобильных браузерах может не срабатывать — поэтому проверка
  канала дополнительно запускается при открытии страницы игры и при сигнале
  `page-ready` от перехватчика.
- `chrome.permissions.request` на Android иногда недоступен: используйте
  уже разрешённые хосты (`raw.githubusercontent.com`, `gist.githubusercontent.com`,
  `*.github.io`, `api.github.com`) либо импорт `update.json` с устройства.
- `options.html`/`ota.html` открываются отдельной вкладкой — это удобнее, чем
  маленький попап.

## Безопасность

- Канал только по HTTPS, без cookie/авторизации на чтение (`credentials: 'omit'`),
  timeout 12 с, ограничение размера ответа.
- Обязательная проверка SHA-256 канонического JSON; опциональная подпись
  ECDSA с закреплённым публичным ключом.
- Белый список полей + проверка типов и границ чисел + валидация regex.
  Неизвестные ключи просто игнорируются.
- HTML из канала экранируется; CSS проверяется на опасные конструкции.
- Удалённый произвольный JS (`hookCode`) по умолчанию запрещён без подписи.
- Токен GitHub не попадает в журнал, состояние и экспортируемые документы.
- Данные пользователя (снимки, сырые перехваты) хранятся отдельно от состояния
  OTA: фоновый скрипт читает/пишет только свои ключи, чтобы не затереть канал.

## Структура

**Плоские файлы расширения (все в корне, идут в ZIP):**
`manifest.json`, `background.js`, `stats.js`, `content.js`, `inject.js`,
`overlay.js`, `popup.html/js`, `style.css`, `options.html/js`,
`ota-config.js`, `ota-core.js`, `ota-updater.js`, `ota.html/css/js`, иконки.

**Репозиторий (не попадают в расширение):**
`ota/source.json` (что правим), `ota/update.json` (готовый файл канала),
`ota/public.key`, `tools/*.mjs`, `.github/workflows/ota.yml`, `release/*.zip`.

## Частые вопросы

**Правка не применилась.** Проверьте «Проверить сейчас» и журнал: там точная
причина (HTTP, CORS, хэш, версия, `minExtension`). raw.githubusercontent.com
кешируется ~5 минут — ручная проверка добавляет `?_=…` и обходит кеш.

**Версия в канале не новее.** Применяются только версии старше уже применённой.
Поднимите `version` в документе (кнопка «Шаблон» сама предлагает следующий
номер).

**Изменил CSS/подписи, но игра не обновилась.** Эти правки приходят живым
сообщением; если вкладка была открыта до установки обновления — нажмите
«Обновить» в оверлее. Для `hookCode` нужна перезагрузка вкладки.

**Хочу вернуть как было.** «Откатить последнее обновление» или «Сбросить всё
к заводским». Снимки и история наблюдений сохраняются.
