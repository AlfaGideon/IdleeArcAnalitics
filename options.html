Расширение раз в час читает update.json из репозитория, проверяет SHA-256 (и, если настроено, подпись ECDSA) и применяет правки: лимиты перехвата, регулярки, подписи метрик, CSS оверлея, объявления и — из подписанного канала — новый код перехватчика. Всё это можно поменять прямо из расширения, в том числе опубликовав файл на GitHub через API. Подробности — в README.md.

Расширение только читает данные, которые игра и так получает от сервера, и считает статистику. Оно не нажимает кнопки, не отправляет запросы от твоего имени и не меняет сохранение.

Как расширение получает данные

IdleArc — это Flutter-приложение: интерфейс нарисован на <canvas>, поэтому «выделить текст» и прочитать HTML нельзя. Зато игра общается с сервером по HTTP:

  1. Контент-скрипт внедряет крошечный перехватчик в контекст страницы до загрузки игры.
  2. Перехватчик оборачивает fetch, XMLHttpRequest и WebSocket, копируя только JSON-ответы idlearc.com/api/*, в которых встречаются характеристики.
  3. Из ответов вытаскиваются числа (attackDamage, maxHealth, combatStats…) и превращаются в «снимок» — набор характеристик на момент времени.
  4. Снимки складываются в chrome.storage.local. Когда характеристика меняется — появляется новая точка.

Откуда берутся «базовые параметры»

Чисел, которые игра не показывает, два вида, и у них разные источники:

Что ищемОткуда берём
Коэффициенты статов, стоимость апгрейдов, таблицы монстров Публичный конфиг https://idlearc.com/api/config/game — отдаётся без входа в аккаунт, ~640 КБ. Расширение качает его и показывает во вкладке «Справочник».
Как твои статы растут с уровнем/предметами Подбор по твоим же наблюдениям: метод наименьших квадратов сравнивает линейную, квадратичную, степенную и экспоненциальную модели и выбирает лучшую по AICc.
Стоимость следующей прокачки Две цены из игры дают точный шаг геометрической прогрессии: g = (c₂/c₁)^(1/n) − 1.

Как правильно собирать точки

  • Сделай снимок → измени ровно один параметр в игре (вложи очко, надень предмет) → дождись нового снимка.
  • Меняй один параметр за раз — иначе не понять, что повлияло на результат.
  • Для надёжной формулы нужно минимум 3 разные точки, лучше 5–8.
  • Если ось X — «индекс шага», формула описывает чистый прирост шага. Если ось X — «уровень персонажа», получишь зависимость «стат от уровня».

Как читать результат

R²Значение
≥ 0.999Модель совпадает с игрой (возможно, это и есть настоящая формула)
0.99–0.999Очень близко; часто округление в интерфейсе
0.95–0.99Хорошее приближение для прогноза
< 0.95Формула сложнее выбранной модели — добавь точек или другой оси

Модели сравниваются по AICc: если несколько подходят одинаково, расширение предпочитает более простую.

Файлы данных

Экспорт/импорт — JSON с массивом снимков. Удобно перенести историю на другой компьютер или поделиться с другими игроками.

Ограничения

  • Расширение видит только те числа, которые сервер реально присылает. Если игра считает что-то на клиенте «на лету» и не показывает, этого числа не будет.
  • Формула урона в IdleArc многоступенчатая (база → аддитивные % → плоские добавки → отдельные множители). Калькулятор считает ожидаемый удар с критами и двойными ударами, но не моделирует все слои сразу — для полной картины нужны эксперименты по слоям.
  • Обновления игры меняют конфиг. Кнопка «Обновить» в Справочнике перекачивает его заново.
